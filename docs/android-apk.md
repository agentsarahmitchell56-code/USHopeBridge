# HOPEBRIDGE Android test APK

## Current implementation

The Android project is generated by Capacitor 8 in GitHub Actions. The first customer-test APK opens the existing HOPEBRIDGE application flow at:

- https://us-hope-bridge.vercel.app/apply

The existing Next.js application remains the source of truth for applications, status tracking, support conversations, uploads, authentication, and staff access. No Supabase schema or customer records are changed by this Android wrapper.

## Build a test APK

1. Open the GitHub repository.
2. Select Actions.
3. Select **HOPEBRIDGE Android APK**.
4. Select **Run workflow** on the branch containing this change.
5. After the workflow succeeds, download the `hopebridge-android-debug-apk` artifact.
6. Extract `app-debug.apk` and install it on an Android test phone.

The debug APK is for controlled testing. It is not a Play Store release and is not signed with a production upload key.

## Important limitations before public release

- This first APK loads the hosted website over HTTPS; it requires an internet connection.
- The initial wrapper does not add native push notifications or offline application submission.
- The APK must be tested on real Android devices for sign-in, application submission, status lookup, chat, image/video upload, file chooser, keyboard behavior, and external links.
- A production release needs a deliberate signing-key custody process, app versioning, privacy/data-safety review, and a release build. Never commit signing keys or passwords to this repository.
- Google Play publication is a separate approval and is not performed by this workflow.
